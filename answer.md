Question 1: What is version control, and why is it important?

Version control is a system that keeps track of every change made to your files over time. Every time you update and save your work, it records that step as a numbered version, like version 1, version 2, and version 3. 

It is important because it keeps your work safe if your computer crashes, lets you see exactly what was edited, and allows you to jump back to an older draft whenever you make a mistake.

For example:- When working on a college project, many students save separate copies like `project`, `final_project`, and `really_final_project`. Version control keeps everything in one clean folder and tracks the whole history behind the scenes, just like the edit history in Google Docs.

---

Question 2: Why do developers use Git?
Developers use Git because it is a fast, reliable tool that runs directly on their own laptops to manage their code. It creates a safe storage area called a repository, lets developers choose which files to save, and records a short message explaining why each change was made.

For example:- If a developer adds a new login button to an app, they use Git to save a snapshot of that specific change. If the new button breaks the app the next day, they can undo it in seconds instead of having to rebuild the whole project from scratch.

---

Question 3: What common problems does Git solve?

Git solves the everyday headaches that come with writing and managing code:

Losing work:- It protects your files if your computer crashes or you forget to save.

Messy file clutter:- It stops you from saving multiple confusing copies of the same file.

Making mistakes:- It works like a time machine so you can return to any earlier working draft.

Mystery edits:- It records who made a change, the exact time they made it, and why.

Team mix-ups:- It prevents teammates from accidentally overwriting each other's code.

For example:- If you are working on a group presentation and someone accidentally deletes your slide, Git lets you restore that exact slide immediately without starting over.

Question 4: What is the difference between Git and GitHub?

Git is the local tool installed on your computer that tracks your files and saves your versions. GitHub is a website where you upload and store those Git projects online so you can share and collaborate on them with other people.

For example:- Git is like a private notebook inside your backpack where you write and date your notes every day. GitHub is like putting a copy of your notes on a class website so your friends can read them and add their own ideas.

---

Question 5: What is the difference between centralized and distributed version control systems?

In a centralized system, all the files and history live on a single main server. If you lose your internet connection or the server goes down, you cannot save versions or view older drafts. 

In a distributed system (like Git), every person has a complete copy of the whole project and its history right on their own laptop, meaning you can save versions and work completely offline.

For example:- A centralized system is like a single whiteboard in a classroom—you can only read and write on it if you are in that room. A distributed system is like every student having their own printed notebook—you can write and study anywhere, and sync notes with your classmates later.
